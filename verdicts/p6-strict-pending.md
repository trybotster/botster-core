### R1-2 MEDIUM — a held id without a transcript avoids its required passing run

`pending::held_problems` checks duplicate ids, pending membership, and overlap with real-only ids.
It does not require a held id to have a transcript.
In `tests/conformance.rs`, the no-transcript branch creates an ignored trial before `strict_trial` can classify the id.
The strict report still includes the entry in its held count.

The pinned Core inventory contains 68 pending ids without transcripts after withdrawal and deferral filtering.
One example is `conf::a13_1_all_representations_one_event_atomic`.
A valid held line for this pending id passes the current membership checks.
The harness then ignores the id instead of requiring a passing result.
The same problem can leave an existing held entry unchecked after a transcript disappears at a pin change.

Both current held entries have transcripts. This finding concerns validation of held entries, not their present membership.
The declared held rule requires a passing run and prevents stale entries.
Ordinary pending ids without transcripts can continue to report themselves ignored.

Reject a held id without a transcript.
Add a public input/output proof for this failure condition.
The reviewer sent this finding directly to P3 and Astra.

### R1-3 LOW — an empty authority passes held-line parsing

`parse_held` uses `status::clause` to read its required authority field.
That helper removes parentheses and accepts `()` as empty text.
For example, `conf::a  budget  owner: p  ()  because: y` returns a held entry with no authority.
The current tests reject missing parentheses, but do not reject an empty authority.

Reject empty authority text in held-line parsing.
Add a malformed-line proof for this case.
The reviewer sent this finding directly to P3 and Astra.
