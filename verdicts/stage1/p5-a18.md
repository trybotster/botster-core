### R1-1 — HIGH — Adopted starts do not initialize the idle timer

The new initialization in `adopt.rs:399-400` runs only through `post_adoption`.
`adopt_report` sends a Starting row with NotLaunched or Spawning to `adopt_start` instead (`adopt.rs:258-260`).
An Adopt retry whose worker reports Spawning takes that same start path.

`flows.rs:191-205` posts Running for this adopted start and records the final row when `f.adopted` is true.
It never initializes `silence.idle_start`.
`finish_start` later calls `adoption_posted`, which completes the adoption operation but also does not initialize the timer.
Neither path calls `post_adoption`.

For an adopted session with no output, `idle_start` therefore remains None.
Setting a silence threshold cannot produce a deadline: `Silence::deadline` requires both the threshold and idle start.
Silent never becomes due on these successful adoption paths. This violates A18-2.
The defect also prevents the host from reporting the required adoption unix time as `since`.

Initialize the idle start at the pump that posts Running for each adopted start path.
Do not use the later completion pump as the adoption point.
Add behavior proofs for NotLaunched, Spawning, and an Adopt retry with Spawning.
Check no early Silent, the event at the threshold, and `since` equal to the Running-post pump's unix time.

The new test uses `running_payload()`, which takes `post_adoption`, so it does not cover these paths.
Existing adoption tests exercise all three start paths but do not assert silence behavior.
The package reviewer independently reported the same defect as A18-F1 MEDIUM.
Integration classifies the missing required behavior as HIGH. Both findings require the same correction.
