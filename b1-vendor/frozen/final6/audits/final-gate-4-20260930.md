# Final gate 4 audit (2026-09-30)

Auditor: read-only contracts auditor. No file was changed except this new file. No cargo, no tests, no messages.

## 0. The gate

Gate 4, as the orchestrator redefined it today:

- **(a)** Every normative clause of every contract names at least one conformance test id.
- **(b)** The seven cutover-e2e journeys J1 to J7 match the final contracts.

Running the suites is a later BUILD gate. This audit does not run them.

**Verdict: FAIL.** 12 behavioral clauses name no test id (1 in Hub→client, 11 in the Lua binding). 4 journeys need an update (J1, J3, J6, J7).

## 1. Method

- Files (under `~/botster-sessions/shared/`): `core-contract-v1.16.md`, `route-codec-v1-extract-rev26.md`, `hub-client-contract-v1-candidate-parity40.md`, `hub-plugin-contract-v1.1.joint-J3.md`, `hub-plugin-lua-binding-v1.1-A4r77-r2.md`, `ui-contract-v1-frozen-20260930.md`, `ui-contract-v1.1-amendment-candidate4.md`, `ui-contract-v1.2-embed-frozen-20260930.md`. Journeys: `audits/gate4-suite-traceability-20260930.md`, addendum table B and its source items.
- A clause row is a table row whose first cell is an id of the form `XX-n`, `XX-nb`, `XX-Ln`, `UI-XX-n` (for example `TB-L2`, `PR-7b`, `UI-RZ-2e`). A row continues on the next lines until the next table row or heading. A line that starts with "| `conf::" is a continuation.
- A row "names a test" when its Test column holds at least one `conf::` id. The auditor checked that every id sits in the Test column and not only in the clause text. No row takes its ids from prose after the table.
- The Lua binding has no clause table. Its clauses are the bullets `LB-1` to `LB-18` (section A). Its tests are one list in section F.
- A duplicate is one test id in two different clauses of the same contract.

## 3. Journeys J1 to J7

Every clause id that a journey (or its source item) names still exists in the final files. The one gap is behavior, not ids. Details follow.

### J1 Attach and type on each binding — NEEDS UPDATE

- Names: HC TB-0, BP-1, BP-4, TS-4, TS-5; source items 30 and 13 (TR-2, TR-3, TS-8, TS-11, HP SS-5). All exist.
- Changed behavior it relies on:
  - The `webrtc` leg needs a paired credential (TS-1 `binding_auth_unavailable` without one). Pairing now needs the **web plugin**: it provides the origin (PR-0, HP WP-1) and the signalling relay (PR-4, HP WP-2 to WP-4). The journey does not set this up.
  - Input is fire-and-forget (TS-5, TS-5b, TS-5c). The journey must assert no success frame for keys and text. A paste is answered only when it requests `want_result: true` (`input_done`), or when it is refused (`input_refused`).
- Proposed text:
  > **J1 Attach and type on each binding.** `local-stream` from the TUI; `webrtc` from the Web client and from a TUI over `webrtc`. Setup for `webrtc`: install and enable the web plugin fixture, approve its `web_origin` and `relay_signaling` grants, and pair (J3). Type and see the echo; no success frame arrives for keys or text. A paste with `want_result: true` gets `input_done`; a paste over `max_paste_bytes` gets `input_refused{too_large}`. A forged route offer is refused. Detach gives `route_closed{detached}`; a re-attach gives a new `route_id`. Proves HC TB-0, BP-1, BP-4, TR-2, TR-3, TS-4, TS-5, TS-5b, TS-5d, TS-8, TS-11; HP WP-2 to WP-4.

### J2 Hub restart with bytes flowing — MATCH

### J3 Pairing — NEEDS UPDATE

- Names: HC PR-0 to PR-9; source item 29 (TR-5). All exist.
- Changed behavior it relies on: the web origin and the signalling relay are now the web plugin's (PR-0, PR-4, HP WP-1 to WP-4, WP-6). With no web plugin origin, `issue_pairing` is refused `wrong_state{no_web_origin}`.
- Proposed text:
  > **J3 Pairing through the web plugin.** With no web origin, `issue_pairing` is refused `wrong_state{no_web_origin}`. Enable the web plugin fixture, set the origin (`web.set_origin`) and the ICE servers (`web.set_ice_servers`). Issue a link: its URL uses that origin. Pair a browser: signalling goes to `<web origin>/hubs/<hub_id>/signal` through the plugin relay, and the plugin never sees a secret, a key, a signature or route bytes. Reconnect with `auth_response`. A Hub restart invalidates an unused link. `delete(client_credential)` closes the live connections and routes of that credential. A forged answer fails authentication. Proves HC PR-0 to PR-8, TR-5; HP WP-1 to WP-4, WP-6.
- Contract inconsistency found (fix before the freeze): HP **WP-1** says `web.set_origin{origin: null}` "restores the Hub default". HC **PR-0** says that with no web plugin origin `issue_pairing` is refused `no_web_origin`, so there is no Hub default. One of the two must change. Also, WP-1 cites WP-3 for the served origin; static serving is WP-5.

- Names no clause. The behavior exists: HP NT-10 defines the "Telegram-shaped run" (a long poll with a secret, a send, unload during a pending poll).
- Recommended text (names the clauses):
  > **J5 Telegram.** Install the plugin, approve its `net` allowlist and its secret, enable it. It long-polls `getUpdates` with `{{secret:bot_token}}` as an async `http.request` (answer `queued`, completion on `operations.on`), then sends a message. ### J6 Plugin crash and reload — NEEDS UPDATE

- Names: "HP lifecycle and EV-12/13"; source item 34 (LD-1, LD-3, CR-2, CR-3, CR-5, CR-8). All exist.
- Changed or wrong behavior: "subscribers see gaps" does not match the contract. A crash loses event copies **with no replay and no gap marker** (EV-4). A producer reload keeps the subscription (EV-7). A gap marker comes only from queue overflow (EV-12, EV-13). A session-family subscriber gets a fresh baseline after a delivery or handler failure (EV-6). Plugin management now exists: install, grant approval, reload and quarantine are client verbs on `package` and `quarantine` (HP PM-5, PM-8; HC A.7, A.9).
- Proposed text:
  > **J6 Plugin crash and reload.** Install from a `local` source, `approve_grants`, enable. Crash the plugin: in-flight calls fail `plugin_crashed`; its pending safe writes end `cancelled{plugin_unloaded}`; its network work is cancelled; it restarts once, and a second crash in `restart_window` quarantines it (a `quarantine` row; `invoke(quarantine, resolve)`). The Hub stays up and another plugin is not affected. Lost event copies are not replayed; a consumer of the crashed producer keeps its subscription; a session-family subscriber gets a fresh baseline; state comes back from the plugin store. `invoke(package, reload)` with a failing candidate keeps the old instance serving. After a Hub kill -9 the plugin is re-adopted and its tool answers. `plugin_log` shows a `restarted` marker. Proves HP LD-1, LD-3, LD-5, CR-2, CR-3, CR-5, CR-7, CR-8, EV-4, EV-6, EV-7, SW-5, NT-8, PM-5, PM-8.

### J7 The workspaces UI — NEEDS UPDATE

- Names: HC section 7b and the ui-contract vocabulary; source item 37 (HP VW-1 to VW-7, EN-9; HC SF-0 to SF-2, DS-6). All exist.
- Changed behavior it relies on: item 37 says "A session caller cannot subscribe". HP **EN-9** now says the caller is a client caller: an operator, **or an agent that holds the permission** (CP-9, HC MC-1b). A caller without the permission is `capability_denied`.
- Mismatch inside the journey: the title says "the workspaces plugin kinds", but source item 37 is the messaging inbox fixture (HP VW-7). Name both.
- Proposed text:
  > **J7 Plugin views in Web and TUI.** Views of the workspaces plugin and the HP VW-7 messaging inbox fixture. A post appears in the view; an ack through a UI action removes the row; an unrelated delta reaches every watcher (one shared projection). A caller without the client permission is refused `capability_denied`; an agent that holds it sees the same projection. A stale descriptor dispatches nothing. A navigation with a `select` preset opens the target view with the slot set, and the Web URL restores it. An `embed` part renders sandboxed in Web and as an "open in browser" line in the TUI. Proves HP VW-1 to VW-7, EN-9; HC SF-0 to SF-2, DS-6; ui-contract UI-SL-5, UI-SL-6, UI-EM-3, UI-EM-6.
