## E1. The part

`embed` is one new part, in the data class (it binds a page), and it is the only new part.

```
Part embed = { type: "embed", id, title,
               page: { asset: Operand },     // the plugin asset reference (E2); a literal or a row field
               channel?: { from_page: [ { type, invoke? | select?, args? } ],
                           to_page:   [ { type, source: Source, fields: [Path], on: "change" } ] },
               empty, error }
```

## E2. Serving side (agreed with 0016; HP A4r55 section 9.13 AS-1..AS-4 owns the clauses)

The ui-contract states only the properties a client needs. The plugin-platform writer (0016) owns the serving clauses. Agreed text in HP A4r59 (was A4r55): `assets.publish` (surface `assets`, bare, named "publish web pages"), staged manifest `assets`, a separate listener `assets_listen`, a one-asset one-viewer token that expires after the Hub parameter `asset_token_ttl_ms`, and the headers below. Summary:

- A host call **`assets.publish{ name, content_type, bytes_b64 }`** (grant surface `assets`, scope `assets`) stores one immutable asset in a Hub-owned, per-plugin, quota-bound store and returns `{ asset_id }`. A republish under the same `name` makes a new `asset_id`. The plugin may also declare static assets in the package (staged at load, same store).
- The Hub serves an asset only at **`GET <assets origin>/<plugin-key>/<asset_id>?t=<capability>`**. The assets origin is **a different origin from the app** (a separate port or host name, no shared cookies). The capability token is issued to a client that may show the view, is scoped to one asset and short-lived; it is the only credential, and the app's credentials are never sent (and are never valid there).
- **Response headers, CSP and the network boundary are HP AS-3 (A4r63) only.** This contract copies no header text. The client-visible result is UI-EM-12(b).
- **Asset lifecycle is HP AS-4 (the Hub→plugin contract), not restated here.** Assets survive crash, restart and reload, and are deleted on disable, uninstall or quarantine. No asset from one plugin is readable with another plugin's path. UI consequence: **a runtime-published asset** (`assets.publish`) still resolves by its `asset_id` and `name` after a crash, restart or reload. **Staged assets** (the manifest `assets` list) are replaced as a set by each version: a staged `asset_id` or `name` that the new version no longer lists is `not_found`, and the contract does not promise it resolves. After disable, uninstall or quarantine every `open_asset` is `not_found`. In each `not_found` case the part shows `error` and the channel is already retired (UI-EM-13: asset change or revocation).

## E3. The message channel

Both directions are JSON messages `{ "botster": 1, "type": "<name>", "payload": <json> }` over `postMessage`. Only **declared** types pass. Everything else is dropped.

## E5. Scope and risk notes

- **Trust.** The page is untrusted plugin content, like plugin Lua (TR-2). The threats handled here: reading the app's origin (no `allow-same-origin`, separate origin), script network requests (`connect-src 'none'`; self-navigation is covered by UI-EM-12), navigation of the app (no `allow-top-navigation`), credential leakage (UI-EM-4), cross-plugin reads (per-plugin path and token), message abuse (declared types only, canonical schema). Not handled: a page that shows misleading content inside its frame (visual spoofing); the client SHOULD mark the frame with a visible border and the `title`.
- **Kit note (TUI, F3):** the TUI kit must wrap `text` nodes and size them by wrapped height for UI-SA-5's "does not truncate" rule; kit work, no contract change.
- **Not in this amendment:** the asset store, quota and token clauses (HP), the link-out URL form beyond UI-FD-1, plugin-supplied scripts for any other part (still excluded: P1).
- **Closed with 0016:** the assets origin is the operator-configured `assets_listen`; the token lifetime is the Hub parameter `asset_token_ttl_ms` (no number here); both `assets.publish` and staged assets are v1.
