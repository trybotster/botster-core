# Hub→plugin contract v1.1, Amendment 8 (candidate 2): interface fail-closed rules in v1, and breaking changes in the upgrade preview

The base is the Hub→plugin contract of `frozen/current` (manifest final30): v1.1 joint J4e, with Amendments 1 to 7, which are unchanged except where A8-3 names a replacement. Other contracts are cited by contract name and clause id only.

**Supersedes candidate 1** (`1e774a16…5bf9`, commit `ddab9e4`), which the Amendment reviewer rejected (verdict `b69777f`):
1. A8-2 did not keep result types and array items, so a MINOR could change a result property's type. A8-2 now uses a recursive relation over the whole PD-3b subset.
2. A8-1 gave two outcomes for an unknown optional object with a required child. A8-1 now fixes the traversal: the Hub judges an unknown property once, at its own place, and never looks inside it.
3. A8-1 now says explicitly that A8-2 compares documents only, so a provider export may still add required result properties (PD-3b(c) is unchanged).

Author: the contract steward. Reviewer: the Amendment reviewer (Sol). Date: 2026-10-02. Found by the hp-manifest pair, through the Stage 0 lead (`conf::pd_4_consumer_fails_closed_on_unknown_required_field`, `conf::pd_6_breaking_upgrade_shown_in_the_preview_and_refused_unless_accepted`).

**Why.**
- **PD-4** says "a consumer fails closed on an unknown required field or kind (it refuses the answer with `invalid_request{detail.code: interface_unknown_required}`)", and "a provider refuses a call with an unknown required argument". No clause names the party that makes these checks, or the schema that makes a field "known" or "required". PC-1 returns the callee's `result` with no check. In v1 an interface is a set of calls only (PD-3), so no kind can occur. No clause says how "a MINOR version only adds" is checked.
- **PD-6** says that a breaking upgrade "is shown in `preview_upgrade`" and "is refused unless the caller accepts it". No clause names the preview field or the refusal. The `botster` CLI spec (CLI-PL4, and its error table) already prints `conflict{breaking_not_accepted}` with `detail.consumers`. The Hub→plugin contract does not define that code.

**Terms used below.**
- The **bound document** of a consumer requirement is the interface document whose hash the lock records for that binding (PD-6, PM-3 `interface_hash`).
- The **export schema** is the provider's declared `args_schema` or `result_schema` for the tool (PD-3).
- **At the same place** means at the same property path, through `properties` and `items` (the PD-3b schema subset). Every element of an array is at the place of its schema's `items`.
