# ui-contract 1.4 amendment (candidate 1): what `realize` emits

Owner: the contract steward. Reviewer: a Sol named by the orchestrator. Date: 2026-09-30. MINOR 1.4, feature `ui_1_4`. **This file is the amendment, in the post-freeze amendment path.** The base is the ui-contract of `frozen/final6` (1.0, 1.1, 1.2 successor2, 1.3 candidate9), which is unchanged. This amendment cites other contracts by name and clause id only.

**Why.** The Foundation build of `botster-ui-contract` found items that `realize` must emit, and that the vectors therefore fix. Neither a frozen clause nor the adopted UiNode schema names them (steward ruling R-2.3). The UI section 16 rule applies: every renderer is checked against the same vectors, so whatever a vector asserts is normative.

**Adopted vocabulary.** The UiNode kinds and the per-kind prop schema are the existing `botster-ui-contract` `UiNode` (UI section 12), taken from `botster-hub@9e1ba42803eeab4856181e4012d3435f9a763949:crates/botster-ui-contract/src/lib.rs` (ruling R-2.3). This amendment **adds** to that vocabulary. It removes nothing.

## Part A. Props added to the UiNode schema

| # | Clause | Test |
|---|---|---|
| UI-NV-1 | **Added props.** These props join the per-kind schema. Each takes its value only from the clause that names it, and a prop with no value is omitted (UI-RZ-2a):<br>- `state`: `"loading"`, `"empty"` or `"error"`, on `list`, `table` and `panel` (UI-CP-1);<br>- `collapsed: bool` on `form_section` (UI-FM-6);<br>- `read_only: bool` on `text_input`, `textarea`, `checkbox` and `select` (UI-FM-5, UI-CF-3);<br>- `masked: bool` and `input: "text" \| "number"` on `text_input` (UI-FM-1, UI-FM-2, UI-FM-8);<br>- `indent: bool` on `stack` (the UI-CF-2 panel and section fallback);<br>- `name` on `embed`, beside `asset_id` (UI-EM-1 `{ name }`; UI-RZ-2f);<br>- `selected: bool` and `activate` on each `table.rows` entry, beside the adopted `{ id, cells, action }` (UI-SL-1, UI-SL-3). | `conf::ui_nv_1_added_props` |

## Part B. Renderer capability names (section 11)

| # | Clause | Test |
|---|---|---|
| UI-CF-5 | **Capability values.**<br>- `parts`: the part kind names of the view grammar.<br>- `widgets`: the `ui` widget hint values of the grammar.<br>- `features`: the ui-contract feature names (for example `ui_1_1`, `ui_embed`, `ui_1_3`, `ui_1_4`), plus `display_metric` and `display_badge` for the field display options that UI-CF-2 can fall back from.<br>- New: `screens: [ "<kind>@<MAJOR>" ]`, the kinds that have the client's own screen (UI-SL-3, DS-4).<br>- **An absent list means "all values of that list"**: a renderer that omits `widgets` supports every widget. An empty list means "none". | `conf::ui_cf_5_capability_values`, `conf::ui_cf_5_absent_means_all_empty_means_none` |

## Part C. Shapes that `realize` emits and reads

| # | Clause | Test |
|---|---|---|
| UI-NV-2 | **Prop value shapes** (the 16 props of UI-RZ-2a):<br>- `confirm`: `{ message, tone? }`;<br>- `activate`: one of `{ select: "<slot>" }`, `{ invoke: "<action id>", row_key? }`, `{ open: { kind, key } }`, `{ navigate: { view, select? } }` or `{ url }`;<br>- `options`: `[{ value, label }]`;<br>- `error` on a field: a string reason (for example `option_unavailable`, UI-FM-4) or the plugin's `field_errors` message;<br>- `absent_reason`: `not_found`, `no_baseline` or `remote_hub_unsupported` (UI-RF-1);<br>- a button's `action`: `{ id, payload: { target, args } }`.<br>An unknown variant is shown as "other" (EN-6). | `conf::ui_nv_2_prop_shapes` |
| UI-NV-3 | **Role segments for overlays and forms** (UI-RZ-2, UI-ID-2), each built by the UI-ID-3 function:<br>- an action dialog is `child(<button id>, "container")`;<br>- the form in it is `child(<dialog>, "item")`;<br>- a form section is `child(child(<form>, "item"), "group:<name>")`, and the advanced section is `"optional"`;<br>- the submit and cancel buttons are `child(child(<form>, "action"), "submit" \| "cancel")`;<br>- the confirm dialog's buttons are `child(<dialog>, "confirm" \| "cancel")`;<br>- a toolbar's overflow menu is `child(<toolbar>, "item")`;<br>- a row's action slot is `child(<row>, "action")`.<br>Admission refuses an author id or a form property named after a role word, or starting with `group:` (UI-ID-1, code `reserved_id`). | `conf::ui_nv_3_overlay_and_form_ids` |
| UI-NV-4 | **RealizedTree fields:**<br>- `root`;<br>- `overlays`, the open dialogs (UI-RZ-2b);<br>- `diagnostics: [{ node_id?, code, detail? }]`;<br>- `local_changes: { cleared_selections, cleared_drafts }`, what `realize` changed, which the renderer applies back (UI-RZ-2d).<br>The diagnostic codes (non-exhaustive; an unknown code shows as a generic diagnostic): `duplicate_node_id`, `unknown_tone`, `unknown_display`, `open_without_screen`, `masked_input_unavailable`, `uneditable_required_property`, `unsupported_view_version`, `unsupported_view_feature`, `unparsable_view`, `row_without_id`, `stale` (UI-AD-2). | `conf::ui_nv_4_tree_fields_and_codes` |
| UI-NV-5 | **Input shapes:**<br>- `local_state`: `{ selections, drafts, overlays: [{ form \| confirm: { action, row_key? } }], focus }`;<br>- each `kind_snapshots` entry: `{ baseline: bool, hub_id?, rows, error? }`. UI-RF-1 finds a remote hub by comparing the snapshot's `hub_id` with the hub_id of the ref's key;<br>- action access comes from the rows of the watched kind `kind`, whose `actions` are keyed by action name (`allowed`, `reasons`; DS-1; ruling R-2.6). | `conf::ui_nv_5_input_shapes` |
| UI-AD-5 | **Admission failure codes.** UI-AD-1's "typed admission failures" are these codes. Each comes with the JSON path of the defect, and a plugin load reports them as the Hub→plugin load failure `invalid_request { detail.code, detail.path }`:<br>- from the frozen text: `unsupported_part`, `unbound_context`, `unknown_view`, `unknown_property`, `bad_property_type`, `embed_source_not_own`, `number_out_of_range`, `non_canonical_map_key`;<br>- named here: `duplicate_id`, `reserved_id`, `invalid_id`, `kind_not_admitted`, `path_not_allowed`, `unknown_slot`, `unknown_ref`, `unknown_action`, `unknown_handler`, `schema_mismatch`, `schema_unsupported`, `unknown_bound_property`, `arg_type_mismatch`, `visible_when_required`, `bad_default`, `when_not_exclusive`, `bad_alternatives`, `bad_placement`, `link_not_text`, `unsupported_version`, `missing_requires`.<br>A new code is a MINOR addition. | `conf::ui_ad_5_admission_codes` |
| UI-NV-6 | **Default copy is client copy** (UI-PT-5 says "defaults are client copy"). `realize` emits a **copy key**, never text, wherever a default applies: `generic_empty`, `generic_error`, `confirm`, `cancel`, `optional_section`, `required_missing`, `form_unavailable`, `view_unavailable { view_id }`. Each renderer maps a key to its own words. Vectors assert keys, never strings. Authored `Copy` (UI-CP-1) is emitted as text. | `conf::ui_nv_6_copy_keys_not_text` |
| UI-NV-7 | **Defaults:**<br>- `overflow` defaults to `never` (UI-PT-4, UI-PT-5);<br>- `overflow: auto` never moves an item of the highest priority present, so with one priority level nothing moves;<br>- fields with `advanced: true` and no `group` go to the section named `optional` (UI-FM-6). | `conf::ui_nv_7_overflow_defaults`, `conf::ui_nv_7_optional_section` |

**Not changed by this amendment:** the adopted UiNode kind `iframe` stays in the enum as a deprecated kind, and `realize` never emits it (UI-EM-10). `embed` is the frame kind (UI-RZ-2f).
