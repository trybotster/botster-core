# Core contract v1.17, Amendment 13 — candidate 2 (clipboard writes as the terminal model reports them)

The base is the Core contract of `frozen/current` (manifest final29). It is unchanged except where A13-2 names a replacement. Other contracts are cited by contract name and clause id only.

**Supersedes candidate 1** (`ce5ac3f2…cbef`, commit `23d5cda`), which the Amendment reviewer rejected (verdict `9261a68`):
1. EV-3 is now replaced in full, so only one event shape remains.
2. A13-1b defines who owns the OSC 5522 acknowledgement: the worker alone, through the one admission point.
3. `SUCCESS` has one observation point, which is independent of host presence and of event loss.

Candidate 1 superseded **Core erratum 5 candidate 1** (`1f91606c…76e9`, commit `21f4461`). The Amendment reviewer rejected it (verdict `9bab339`): OSC 5522 can target the primary selection and carry several MIME representations, and the erratum defined neither. The answer needs a change to the event's shape, so it is an amendment.

Author: the contract steward. Reviewer: the Amendment reviewer (Sol). Date: 2026-10-02. The facts come from the Stage 1 Core lead's P2, at `trybotster/ghostty@85a8d8eb197c5752887c017c9a3faa6f1dc1969b`, `include/ghostty/vt/terminal.h`.
- One normalized callback serves OSC 52, OSC 1337 `Copy` and OSC 5522.
- It reports `location` (standard clipboard, selection or primary), the exact OSC 52 `selection` string (empty when the program gave none, and empty for the other protocols), and `contents`: every representation `{mime, data}` of one logical value, already decoded, to be committed atomically. A `contents` of length 0 means "clear the destination".
- The callback must reply synchronously. Returning without a reply denies the write. A reply reaches the program only for OSC 5522 (DONE, EPERM, ENOSYS, EBUSY, EINVAL, EIO); OSC 52 and 1337 discard it.

## A13-2. Text replaced

1. **Section 6.2, the `ClipboardWrite` row:** `ClipboardWrite{id, selection, bytes, total_bytes, reason?}` "OSC 52 write (EV-3)" becomes `ClipboardWrite{id, selection, contents, total_bytes, reason?}` "a clipboard write the terminal model recognizes (EV-3, A13-1)".
2. **EV-3 is replaced in full** by: "**Clipboard writes are surfaced.** A clipboard **write** that the terminal model recognizes arrives as `ClipboardWrite{id, selection, contents, total_bytes, reason?}` (A13-1). A write larger than `CoreLimits.clipboard_bytes` (a memory bound, not a filter) is **never silent**: it is surfaced with `contents: none`, `total_bytes` and `reason: TooLarge`. An OSC 5522 write is acknowledged to the program as A13-1b says. A clipboard **read** is a terminal query and follows EV-8." EV-3's two tests stand.
2a. **HC is unchanged:** its raw-output rule already makes the client the actor for the side effect. Its client rule that the renderer suppresses its own autonomous replies (cited by Core EV-8) covers an OSC 5522 acknowledgement.
3. **Core erratum 5 candidate 1** is withdrawn and never published.

A clipboard **read** is unchanged: it is OSC 52 only, a terminal query (EV-8), and its selection keeps EV-8's rule (`s0` when none). Every other clause is unchanged.
