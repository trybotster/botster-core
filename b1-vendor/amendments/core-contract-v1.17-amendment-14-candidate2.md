# Core contract v1.17, Amendment 14 (candidate 2): `clipboard_bytes` bounds every payload byte the model holds for one clipboard write

The base is the Core contract of `frozen/current` (manifest final31), with Amendment 13, which are unchanged except where A14-4 names a replacement. Other contracts are cited by contract name and clause id only.

**Supersedes candidate 1** (`50ef8dfa…831b`, commit `0d2fa62`), which the Amendment reviewer rejected (verdict `3ece4f7`):
1. The size rule did not say how aliases and metadata count. Candidate 2 counts payload bytes only, and it bounds both the decoded payload and the final contents. An alias's entries count in the final contents.
2. The replacement example used consecutive chunks of one MIME type, which append. Candidate 2 uses a model-valid replacement: the MIME type returns after a different one.
3. "May set the model's limit" did not establish a memory guarantee, and it conflicted with R-32's exception for a `clipboard_bytes` above the model's limit. Candidate 2 **requires** the model's limit to equal `clipboard_bytes`, so that exception never arises. It states the guarantee as retained payload, and it states what the bound does not cover.

Author: the contract steward. Reviewer: the Amendment reviewer (Sol). Date: 2026-10-04. Found by the Stage 1 Core lead (audit A6, issue #148), after steward ruling R-32.

**Why.** 9B says `clipboard_bytes` is "the largest clipboard write Core carries (a memory bound; a larger one is reported, never dropped silently)". EV-3, as A13-2 replaces it, calls it "a memory bound, not a filter". A13 measures a write by the sum of its final representations. These facts about the pinned model (libghostty, the only oracle, R-7) come from fork `3f8eb68`, `src/terminal/kitty/clipboard_write.zig`, and they differ from that sum:
- An OSC 5522 write is one transaction of chunks. Its decoded payload is appended to one buffer. Chunks of the same MIME type in a row continue one region. **A MIME type that returns after a different one starts a new region and replaces the earlier one in the final contents, but the replaced bytes stay held until the transaction ends.**
- **An alias** names another MIME type for the same data. Its data is held once, and the final contents list it once per name.
- The model's own limit on the decoded payload of a transaction is 64 MiB by default. It counts payload bytes only, replaced regions included. MIME names, alias names and other metadata are bounded separately by the model, and they are not counted. R-32's fork patch makes a write over that limit reach the callback, with no contents and its decoded payload size.

So, at a 64 MiB model limit with a 1 MiB `clipboard_bytes`, the model may hold 64 times the stated bound. At a model limit of 1 MiB, A13 would require `SUCCESS` for a write whose final sum is small but which the model did not carry.

## A14-4. Text replaced

1. **A13-1, "Size":** "`total_bytes` is the sum of all representations' byte lengths. Over `CoreLimits.clipboard_bytes`, the write is surfaced with `contents: none`, `total_bytes` and `reason: TooLarge`" reads with A14-1 and A14-2. The bound applies to the write's size. A posted write's `total_bytes` is its contents size, and a `TooLarge` write's `total_bytes` is its size.
2. **A13-1b, the status:** "the write's total bytes are within `clipboard_bytes`" reads "the write's size is within `clipboard_bytes`", and "the write is over `clipboard_bytes`" reads "the write's size is over `clipboard_bytes`" (A14-2).
3. **9B, `clipboard_bytes`:** "the largest clipboard write Core carries" means the largest write size (A14-1). The model's own decode limit equals it (A14-3).
4. **Steward ruling R-32**, the case of a `clipboard_bytes` above the model's limit: it no longer arises (A14-3). The rest of R-32 stands.
5. **A13's oversize and acknowledgement tests** (`conf::a13_1_too_large_counts_all_representations`, `conf::a13_1b_over_bound_is_io_error`) are measured by the write's size. Their existing cases, with no replaced region and no alias, keep their results.

Every other clause is unchanged.
