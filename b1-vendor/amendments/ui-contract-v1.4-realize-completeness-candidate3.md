# ui-contract 1.4 amendment (candidate 3): what `realize` emits

Owner: the contract steward. Reviewer: the Amendment reviewer (Sol). Date: 2026-09-30. MINOR 1.4, feature `ui_1_4`. **This file is the amendment, in the post-freeze amendment path.** The base is the ui-contract of `frozen/final6` (1.0, 1.1, 1.2 successor2, 1.3 candidate9), which is unchanged. This amendment cites other contracts by name and clause id only.

**History.** Supersedes candidate 2 (`6a33b4bf…88ef`, commit `c693231`). The changes answer the Amendment reviewer's second REJECT (`verdicts/amendments.md`, commit `8cbb821`):
1. `realize` never discards a draft or an overlay. A draft or overlay whose property or button is gone is **kept and not shown**, so UI-AC-7(b) holds across a descriptor re-read (UI-NV-4, UI-NV-5).
2. For one button, a `form` entry always shows before a `confirm` entry, whatever their order in the list (UI-NV-4).
3. Each `errors` entry maps to a defined node. A field error is the field's `error` prop. A form error or an action error is an `error`-tone `text` node that UI-NV-3 places (UI-AC-7(a)).
4. The UI-FM-4 clear is an explicit draft, `{ unset: true }`. It hides the schema default, so the next `realize` finds nothing to clear. The stamped error replaces the field's earlier error. `realize` computes the tree as if its changes were already applied, so the changes do not depend on their order.

Candidate 2 superseded candidate 1 (`bf0b4e00…8360`, commit `8b920a9`). Its changes answered the Amendment reviewer's REJECT (`verdicts/amendments.md`, commit `74e4f4f`):
1. The capability clause is now UI-CF-6. The frozen 1.1 clause UI-CF-5 and every reference to it are unchanged.
2. UI-CF-6 keeps `external_open` (1.1 UI-CF-5) and `embed` (1.2 UI-EM-6) and separates `embed` from `ui_embed`. Each list has its own absence rule. An absent `features` or `screens` list means "none", so UI-CF-5(a), UI-EM-6 and UI-SL-3 keep their fallbacks.
3. UI-NV-3 no longer changes admission. Every new role segment sits below a segment that UI-ID-1 already reserves, or below a node with no authored children. The reserved word set of UI-ID-1 (with `warning`, 1.2 UI-SA-5) is unchanged, and no valid document becomes invalid.
4. UI-NV-4 and UI-NV-5 define every input and output shape. This includes the keys, scroll, stamped errors, refusal errors and reload changes (UI-RZ-2d).
5. UI-NV-6 defines the `Text` value: a JSON string is authored text, and a `{ copy }` object is a copy key. It lists the props that may hold a copy key, and it defines the keys that take parameters.

Also corrected, beyond the findings:
- The `error` prop is now `{ code, message? }`. In candidate 1, a bare string could not tell a code from a message. `required_missing` is now an error code, not a copy key.
- Overlays are keyed by the button node id. An `{ action, row_key }` key could not tell apart two buttons that refer to the same action.
- The default labels of `form.submit` (UI-PT-5) and of UI-RC-5 ("Nothing selected") are now copy keys.

**Why.** The Foundation build of `botster-ui-contract` found items that `realize` must emit, and that the vectors therefore fix. Neither a frozen clause nor the adopted UiNode schema names them (steward ruling R-2.3). The UI section 16 rule applies: every renderer is checked against the same vectors, so whatever a vector asserts is normative (steward ruling R-3).

**Adopted vocabulary.** The UiNode kinds and the per-kind prop schema are the existing `botster-ui-contract` `UiNode` (UI section 12), taken from `botster-hub@9e1ba42803eeab4856181e4012d3435f9a763949:crates/botster-ui-contract/src/lib.rs` (ruling R-2.3). This amendment **adds** to that vocabulary and to the frozen props of UI-RZ-2a, UI-RZ-2e and UI-RZ-2f. It removes nothing.

## Part C. Shapes that `realize` reads and emits

| # | Clause | Test |
|---|---|---|
| UI-NV-2 | **Prop value shapes** (the props of UI-RZ-2a, UI-RZ-2e and UI-NV-1):<br>- `confirm`: `{ message, tone? }`;<br>- `activate`: one of `{ select: "<slot>" }`, `{ invoke: "<action id>", row_key? }`, `{ open: { kind, key } }`, `{ navigate: { view, select? } }` or `{ url }`;<br>- `options`: `[{ value, label }]`;<br>- `error`: `{ code, message? }`. The `code` is a plugin `field_errors` code (UI-FM-7) or a local code: `option_unavailable` (UI-FM-4) or `required_missing` (UI-FM-3 `required_when`, or a required property with no value at submit). The `message` is the plugin's message, when one exists. A renderer shows its own words for a code that has no message;<br>- `absent_reason`: `not_found`, `no_baseline` or `remote_hub_unsupported` (UI-RF-1);<br>- the `action` of a button: `{ id, payload: { target, args } }`.<br>An unknown variant is shown as "other" (EN-6). | `conf::ui_nv_2_prop_shapes` |
| UI-NV-3 | **Role segments for overlays and forms** (UI-RZ-2, UI-ID-2). Each node id is built by the UI-ID-3 function, written here as `child(parent, segment)`:<br>- an action dialog is `child(<button>, "container")`, where `<button>` is the node id of the button that opened it;<br>- the form in the dialog is `child(<dialog>, "item")`;<br>- a form field is `child(<form>, <field_id>)`. This is also its draft key (UI-ID-5). Its generated nodes add `label`, `value`, `widget`, `help` or `error`;<br>- an authored section is `child(child(<form>, "item"), "group:" + <group name>)`. The default section for advanced fields with no `group` (UI-FM-6) is `child(child(<form>, "item"), "optional")`, which differs from an authored group named `optional`;<br>- the submit and cancel buttons are `child(child(<form>, "action"), "submit")` and `child(child(<form>, "action"), "cancel")`;<br>- the buttons of a confirmation dialog are `child(<dialog>, "confirm")` and `child(<dialog>, "cancel")`;<br>- the overflow menu of a toolbar is `child(<toolbar>, "item")`;<br>- the action slot of a row is `child(<row>, "action")`;<br>- the form-level message of a form is an `error`-tone `text` node `child(<form>, "error")`. It is the first child of the form (UI-AC-7(a), UI-FM-7);<br>- the failure message of an action run directly or from a row is an `error`-tone `text` node `child(<button>, "error")`. It immediately follows its button, in the same parent (UI-AC-7(a) "next to that action"). When the button is in an overflow menu, the node follows the menu instead.<br>**No new reserved words.** Each new segment (`submit`, `cancel`, `confirm`, `optional`, `group:…`) appears only below a segment that UI-ID-1 already reserves (`item`, `action`), or directly below a dialog, which has no authored children. Therefore no authored id or property name can collide with one. The reserved set stays as UI-ID-1 states it, plus `warning` (1.2 UI-SA-5). UI-AD-1 and UI-FM-7 are unchanged, and every document that 1.3 admits is still admitted. | `conf::ui_nv_3_overlay_and_form_ids`, `conf::ui_nv_3_property_named_cancel_still_admitted` |
| UI-NV-4 | **RealizedTree fields:**<br>- `root`: the root node;<br>- `overlays`: the dialogs to show. For each button that has an entry in `local_state.overlays` and is in the tree, `realize` shows **its `form` entry when one exists, else its `confirm` entry**, whatever their order in the list (UI-RZ-2b, UI-AC-4). Dialogs of different buttons keep the order in which each button first appears in the list;<br>- `diagnostics`: `[{ node_id?, code, detail? }]`;<br>- `local_changes`: what this `realize` changed in `local_state` (UI-RZ-2d), as below.<br>**`local_changes`** has these fields. Each is a list, and an empty list is omitted:<br>- `cleared_selections: [slot id]`: a slot whose row left its kind (UI-SL-2), or a slot that the document no longer declares (a reload);<br>- `unset_drafts: [draft key]`: a field whose shown value, from its draft or from its default (UI-FM-5), is no longer in its options (UI-FM-4). The renderer sets the draft to `{ unset: true }`;<br>- `stamped_errors: [{ draft_key, code }]`: an error that `realize` itself found. Today the only one is `option_unavailable`, which comes with the matching `unset_drafts` entry (UI-FM-4);<br>- `dropped_view_state: [node id]`: a `focus` or `scroll` entry whose node is no longer in the tree.<br>**`realize` never discards a draft, an overlay or an error.** An entry whose property, form or button is not in the new tree (after a reload, a `stale_descriptor` re-read, a row that left, or a `when` that became false) is **kept and not shown**. When the property or button returns, the entry shows again. This keeps what the user typed across a descriptor change (UI-AC-7(b)). The renderer removes these entries by the rules of UI-NV-5.<br>**One pass.** `realize` computes the tree and `local_changes` as if the changes were already applied. For example, a slot that it clears is already empty when it evaluates the `options_source` that reads the slot. Each field of `local_changes` changes a different member of `local_state`, so the order of application does not matter.<br>**Applying the changes.** The renderer applies `local_changes` to its `local_state` before the next draw (UI-RZ-2d):<br>- it removes each cleared slot;<br>- it sets each `unset_drafts` key to `{ unset: true }`;<br>- it writes each stamped error to `errors.fields`, **replacing** an earlier error for that draft key;<br>- it removes each dropped `focus` or `scroll` entry.<br>On conflict the output of `realize` wins. A `realize` of the updated state gives the same tree and an empty `local_changes`. An `unset` draft shows no value and is not replaced by the default, so the same unavailable value cannot return.<br>**Diagnostic codes** (non-exhaustive; a renderer shows an unknown code as a generic diagnostic): `duplicate_node_id`, `unknown_tone`, `unknown_display`, `open_without_screen`, `masked_input_unavailable`, `uneditable_required_property`, `unsupported_view_version`, `unsupported_view_feature`, `unparsable_view`, `row_without_id`, `stale` (UI-AD-2). | `conf::ui_nv_4_tree_fields_and_codes`, `conf::ui_nv_4_form_before_confirm_in_either_order`, `conf::ui_nv_4_local_changes`, `conf::ui_nv_4_draft_kept_across_reload_and_stale_descriptor`, `conf::ui_nv_4_applied_changes_are_idempotent` (an existing error, a replaced error, and an unavailable default) |
| UI-NV-5 | **Input shapes.** `local_state` holds every item of the UI-RZ-2d rule: drafts, selections, row focus, scroll and overlays. It also holds the errors that the renderer and `realize` stamp. Its shape is:<br>- `selections: { <slot id>: <row key> }`. A slot with no row has no entry (UI-SL-1);<br>- `drafts: { <draft key>: { value } \| { unset: true } \| { clear: true } }`. The draft key is the form field's node id (UI-ID-5, UI-NV-3). `value` is a JSON value: the property's type, or for a UI-CF-3 text editor the edited text. `{ unset: true }` means the field has no value and does not show its default; the request omits the property. `{ clear: true }` is allowed only for a `secret: true` property (UI-FM-8). A property with no entry has no draft and shows its default (UI-FM-5);<br>- `overlays: [{ form: { button } } \| { confirm: { button } }]`. `button` is a button node id. The list is in opening order, and any order is valid input (UI-NV-4);<br>- `errors: { fields?: { <draft key>: { code, message? } }, forms?: { <form node id>: string }, actions?: { <button node id>: string } }`. The renderer writes a refusal here from the invoke result, keyed by the client (UI-ID-4, UI-AC-1b): each `field_errors` entry goes to `fields`, and `Error.message` goes to `forms` for a form, or to `actions` for an action run directly or from a row (UI-AC-7(a)). `realize` also stamps `fields` entries (UI-NV-4).<br>**How `realize` shows `errors`:**<br>- a `fields` entry is the `error` prop of the field node (UI-NV-2);<br>- a `forms` entry is the `error`-tone `text` node `child(<form>, "error")` (UI-NV-3);<br>- an `actions` entry is the `error`-tone `text` node `child(<button>, "error")` (UI-NV-3).<br>The string is authored text (UI-NV-6).<br>**When the renderer removes entries** (renderer rules; `realize` never removes them):<br>- a `fields` entry, when the user changes that field;<br>- a `forms` or `actions` entry, when the user submits or runs that action again, or closes its overlay;<br>- the drafts, overlays and errors of a form, when the user cancels the form or its request succeeds;<br>- any entry, when the view closes.<br>At submit, the client sends only the properties of the current schema (UI-FM-1). A kept draft of a removed property is not sent;<br>- `focus: <node id>`, optional. This is row focus (UI-SL-4);<br>- `scroll: { <node id>: <renderer value> }`. The value is opaque to `realize`.<br>The tree does not depend on `focus` or `scroll`. They are in `local_state` because UI-RZ-2d makes it the single source of truth. `realize` only reports their dead entries (`dropped_view_state`).<br>`kind_snapshots: { <kind name>: { baseline: bool, hub_id?, rows: [row], error?: { message? } } }`. Each row has its `id`, the row key (UI-ID-3). `baseline: false` gives `state: "loading"` (UI-CP-1). UI-RF-1 finds a remote hub by comparing the snapshot's `hub_id` with the hub_id of the ref's key. Action access comes from the rows of the watched kind `kind`, whose `actions` are keyed by action name (`allowed`, `reasons`; DS-1; ruling R-2.6). | `conf::ui_nv_5_input_shapes`, `conf::ui_nv_5_focus_and_scroll_do_not_change_the_tree`, `conf::ui_nv_5_field_form_and_action_errors` |
| UI-AD-5 | **Admission failure codes.** UI-AD-1's "typed admission failures" are these codes. Each comes with the JSON path of the defect, and a plugin load reports them as the Hub→plugin load failure `invalid_request { detail.code, detail.path }`:<br>- from the frozen text: `unsupported_part`, `unbound_context`, `unknown_view`, `unknown_property`, `bad_property_type`, `embed_source_not_own`, `number_out_of_range`, `non_canonical_map_key`;<br>- named here: `duplicate_id`, `reserved_id` (the UI-ID-1 reserved words, unchanged), `invalid_id`, `kind_not_admitted`, `path_not_allowed`, `unknown_slot`, `unknown_ref`, `unknown_action`, `unknown_handler`, `schema_mismatch`, `schema_unsupported`, `unknown_bound_property`, `arg_type_mismatch`, `visible_when_required`, `bad_default`, `when_not_exclusive`, `bad_alternatives`, `bad_placement`, `link_not_text`, `unsupported_version`, `missing_requires`.<br>A new code is a MINOR addition. | `conf::ui_ad_5_admission_codes` |
| UI-NV-6 | **Default copy is a copy key, never text** (UI-PT-5: "defaults are client copy"; UI-CP-2).<br>**The `Text` value.** A prop that can show a default holds `Text = string \| { copy: "<key>", args?: { <name>: string } }`:<br>- a JSON **string** is always authored text, shown literally (UI-CP-3). Authored text equal to a key name, such as `"cancel"`, is still literal text;<br>- an **object** is always a copy key. Each renderer maps the key to its own words.<br>**Props that may hold `Text`:** `label` (button, `form_section`), `title` and `body` (`empty_state`, `dialog`), and `disabled_reason`. Every other prop holds plain values.<br>**Keys:**<br>- `generic_empty` and `generic_error` (UI-CP-2);<br>- `nothing_selected` (UI-RC-5);<br>- `submit` and `cancel` (UI-PT-5, default `form.submit` and `form.cancel` labels);<br>- `confirm` and `cancel` (the confirmation buttons, UI-RZ-2b);<br>- `optional_section` (UI-FM-6);<br>- `form_unavailable` (UI-FM-2, UI-CF-3: the renderer refuses the form);<br>- `view_unavailable`, with args `{ view_id, reason }`. `reason` is the diagnostic code (UI-CF-1).<br>A renderer shows an unknown key as a generic text and counts it (as UI-VR-2 does). It ignores unknown args. Vectors assert keys and args, never words. | `conf::ui_nv_6_copy_keys_not_text`, `conf::ui_nv_6_authored_text_equal_to_a_key_stays_text`, `conf::ui_nv_6_parameterized_key` |
| UI-NV-7 | **Defaults:**<br>- `overflow` defaults to `never` (UI-PT-4, UI-PT-5);<br>- `overflow: auto` never moves an item of the highest priority present, so with one priority level nothing moves;<br>- fields with `advanced: true` and no `group` go to the default section of UI-NV-3, labeled with the key `optional_section` (UI-FM-6). | `conf::ui_nv_7_overflow_defaults`, `conf::ui_nv_7_optional_section` |

**Not changed by this amendment:**
- The frozen clause UI-CF-5 (1.1).
- The UI-ID-1 reserved words, and the `warning` word that 1.2 UI-SA-5 added.
- The UI-RZ-2d rule.
- The adopted UiNode kind `iframe`. It stays in the enum as a deprecated kind, and `realize` never emits it (UI-EM-10). `embed` is the frame kind (UI-RZ-2f).

A client that supports only 1.0 to 1.3 shows a local diagnostic for a view that sets `requires: ["ui_1_4"]` (UI-CF-1). The vectors of this amendment bind every renderer (UI section 16).
