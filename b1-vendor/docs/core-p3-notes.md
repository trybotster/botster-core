# core-p3: feature notes

Feature `core-p3`. It adds 83 Core transcripts for the Stage 1 packages p3-worker and p6-testkit. The files are in `conformance/core/`. The 83 ids are:
- 75 ids that the Stage 1 clause lists (`docs/stage1-clauses/p3-worker.txt` and `p6-testkit.txt` on botster-core `origin/stage1/plan`) mark pending: Core A5-1 to A5-4, A2-2, A2-4, EV-1, EV-3, EV-4, EV-7, ST-1, ST-2, ST-3, ST-5, ST-7 and TP-1;
- the 8 Core erratum 2 ids (E2-1 to E2-3), added by the lead.

Every transcript is `"fake": "structural"` with ruling R-12. The frozen FakeCore is unchanged. Each transcript carries the proof kind that `conformance/replacement-map.json` gives its id. The full run happens against the real Core testkit in Stage 1. One id (`a5_4_suite_runs_real_and_testkit`) is a slow-tier proof: the transcript states the pair of runs and does not claim that it passes here.

## Prior art (BUILD.md, "Starting fresh" rule 0)

- Vault: "a wake test must not consume the one shot edge it asserts" fixed the order of the wake steps (`wake_spurious`, then `wait_wake`, then a pump report). "a non completing shared fake adapter is a blind no progress oracle" fixed every negative assertion: a quiet check names an observer that would change (a later positive event, or a poll after `pump_idle`). "botster workers own authoritative terminal modes and semantic input encoding" fixed the terminal rule: no transcript carries an expected terminal state or byte that libghostty should give.
- Existing transcripts: the 132 on main and core-p1's runner (`foundation/core-runner`, 9a6d8b7) gave the step forms, the route handshake and the `bind_fields` style. This work reuses them.
- botster-core at 053148f: `crates/botster-core-test-support` and the old terminal tests model the old actor vocabulary. Nothing was stolen, so there is no `Stolen-From` commit.
- The p6 edge vocabulary is stated only as Core A5-1 states it (program, storage, process, route transport, wake, scheduler). It is not extended.

## Judgment calls

1. **Joint waits.** A wait that polls the queue (`pump_until`) discards the events that it does not want. So a transcript waits for a write's completion and the events that it needs in ONE `pump_collect`, and it uses `forbid_events` for an event that must never be polled: a forbidden event fails whichever wait polls it (Core E2-3, A2-4, EV-1, EV-7).
2. **Terminal state.** No transcript carries an expected cursor, text or flag value for a terminal. A `ModesChanged` event, `ReadCursor` and `terminal_state` are compared with the libghostty oracle (`oracle_modes`, `oracle_cursor`, `oracle_notification`, `oracle_hyperlinks`, R-7), and the transcript states the relations that the clauses fix (a trimming rule, a wide character is two cells, a changed state gives different flags, a paste is wrapped iff the mode is on). A scenario that needs a mode checks that precondition against the oracle's flags.
3. **One model step.** `program_write_once` delivers bytes as one program write, so the model applies them in one step (E2-3). The initial and final full flags come from the oracle.
4. **Statement steps.** `run_suite`, `check_crates`, `error_codes_reachable` and `run_deterministic` are run by the harness (`CoreHarness::statement`). The driver checks the report. `run_deterministic` compares fresh runs after it numbers each instance by its first appearance, and it checks that an instance names one session (ID-2, EV-9).
5. **A5-2 sources.** Each variation of A5-2 has a source control: `scheduler_order`, `scheduler_hold`, `scheduler_delay`, `scheduler_work_limit`, `scheduler_poll_batch`, `program_write_size`, `route_read_size`, `wake_spurious`, `scheduler_deadline`. The controls act where progress, queue consumption and deadlines arise. A transcript never asserts a pump count, and no control reorders a result that Core already produced.
6. **TP-1.** The clause fixes a byte bound (`tap_inflight_bytes`), not a frame count. `control_link_stats` is a measurement-only control (R-14.3: it injects nothing and is not an edge). It counts at the testkit's in-memory link boundary and never in worker code, adds no wait, lock or synchronization point, and lives only in `botster-core-testkit`. The tap is read with `tap_drain`, which reads until an empty read and sums the drops, because the contract fixes neither the number nor the size of reads.
7. **A5-3.** `error_codes_reachable` names every code at its timing, and the validator rejects a missing code. `Internal` (9.3) and `Cancelled` (A2-2: `WriteInput` never completes with it) have no scenario. `Failed` is real-only (`slow:real-pty`). `fail_next` refuses to script an async code, and the refusal is typed. `CursorReadUnsupported` is reached as R-14.2 says: a cursor read admitted while the session is `Starting` and the process edge withholds the worker's control link (A6-1). The transcript issues that read and asserts the code.
8. **A2-2 (R-14.1).** `named_key` is proven by the clause case: any modifier key written with kitty flag 8 off is `NotWritten(Unsupported{what: named_key})` with exact zero bytes (four keys). Every other `named_key` case and every `wheel_direction` case is real-only, decided by the pinned Ghostty encoder, and the replacement-map note for the id says so with the pin. The transcript also proves `pixel_position`, `produced_text`, `release_event` and `coordinate`, with no permissive alternative.
9. **ST-7.** `facts.input` is the input facts itself, and the validator rejects a matcher field that the schema does not have at that depth. A read of a lost session is `WrongState` (A2-1).

10. **Review round 2.** Buffered events are checked when `forbid_events` starts, and `collect_events` returns them first. `tap_drain` takes `accounted: N` and goes on across pumps and wakes until bytes read plus bytes dropped are N (an empty read is no barrier), and it returns the instance of each chunk. `run_suite` reports the selected and the passed ids: the driver checks that they are the same, complete for the Core suite (the transcripts with the filter, without the statement transcripts) and identical on every harness. `input_records_cost` measures the whole retained record list at the link boundary (R-14.3 conditions). The A5-2 deadline case observes `Stopping` and an armed `next_deadline` before it admits the concurrent operation and advances the clock, and it checks that both are posted by the one pump. Wake cases drain to an idle boundary first. The cancel race has a finished write (`TooLate`), a partly written write and a pre-progress cancel. The `Query` kind: the same oversize bytes first reach an eligible route as a `terminal_query` frame (the worker classifies them), then, with `max_query_bytes` 64, give a `Query` loss and stay in `Output`.

## Controls and steps added

Controls (`docs/core-testkit-controls.md`): the scheduler, process, storage, wake, program and route controls of judgment calls 3 to 6, the oracle readers, `control_link_stats` and `measure_tap_overhead`. The call `tap_read`, the steps `collect_events`, `forbid_events`, `tap_drain`, the typed `expect_refused` and the statements, and the `let` and `check` operations are in the driver (`crates/botster-core-conformance/src/driver.rs`). Their tests are in `tests/p3_steps.rs`. `tests/vocabulary.rs` checks every control argument, step name, event field and statement body.
