# only shrink: the lint fails on an entry that no finding needs. Format: `<id>  step <n>  <reason>`, or `<id>  step <n>  <reason>  <note>`,
# fields separated by two or more spaces; the step is the 0-based top-level index, as the runner numbers it. The note never decides a
# match. It starts with `debt: ` (a planned fix: the owner and the fence) or `exception: ` (why no fence works) (the steward, the R-88
# lint format). A pending id with a debt line is fenced before it is un-pended. Only six reasons exist:
# - `unfenced capture, R-56`: a `pty_input` capture with no `await_pty` of its session since the last write to it whose
#   `min_bytes` is a bound number (R-56 (3)(1)); a number written in the transcript is no fence for a capture.
# - `no program_ready, R-60`: the first host input to a session, with no `program_ready` before it, when a later step asserts the
#   session's output or input log.
# - `no await_title, R-57`: the last `pty_output` of a session before a step that reads the session's events or state without
#   waiting for a new value (or waits for an `EventsLost` marker), with no `await_title` of the session between them (R-61 (a)).
#   The step is the `pty_output`'s.
# - `no output fence before the model read, R-80`: a model read of a session (ReadScreen, CaptureSnapshot, terminal_state, a
#   guarded begin, an attach_route's baseline or a queue_overflow's resync) after an output of the session (pty_output, pty_chunk,
#   program_write_once or uncarriable_sequence) with no output fence between them. The step is the read's. Each entry has a note
#   (steward rulings R-80 and R-88).
# - `unfenced route read, R-56`: a `route_expect_pty` with no `await_pty` of its route's session since the last write to it that
#   covers the read's floor (R-83). R-83 allows one entry only, the transcript that R-81 rewrites; a comment above it says so.
# - `no report fence, R-88`: a read of state or events that a worker's report sets, while a cause of that report has no fence
#   that proves Core consumed it (fence_lint/report.rs). The step is the read's. Each entry has a note (steward ruling R-88).
